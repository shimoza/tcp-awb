# Attacker review of 2026-10-13

Scope: the code that changed between 2026-10-08 and 2026-10-12 in the build queue and its runner (`awb/buildrun.py`,
`awb/build.py`, the build units and scripts of `seal/`), OBS signing through the key service and the XML parsing of
OBS answers (`awb/tcp/keys.py`, `awb/obs.py`, `awb/tcp/cloud.py`), the egress filter (`awb/egress.py`,
`seal/egress/work-egress.nft`), the guard of the tests (`tests/conftest.py`) and the MCP server of TCP Facts
(`awb/tcp/tcp_facts_mcp.py`).

The model, from `CLAUDE.md`, `README.md`, `seal/README.md` and `INTERFACES.md`: a work session (user `awb`) never
reaches the register of names, the owner's keys or the network outside its allow list; a build task (user
`awb-build`) never reaches the host, the vault, the tenants or GitHub; the tests never reach the real host.

The review read the code. It ran no systemd unit, no nft and no root step: a finding about those is read from the
code and the documented behaviour of systemd and nftables and says so.

Each finding has a severity, a place, an attack or failure, the fix and its state: fixed (with its commit, a test
that failed before) or open.

## Fixed

### E1, high: connections opened in mode count kept working after enforce (fixed, 06947a7)

`chain work` begins with `ct state established,related accept`. `awb egress enforce` reloads the table and leaves
conntrack as it is. Attack: in mode count a session opens a long-lived TCP connection (or a UDP flow kept alive) to
any host and stays quiet. The counters count only the first packet of a new connection, so the 24-hour window shows
nothing once it is older than the window (or with `--accept web`), the switch passes: every later packet is
established and accepted. Fix: mark what the allow rules accept (`ct mark set 0xa0b001` on the `c_allowed` rules) and
accept `established,related` only with that mark; in count, unmarked established traffic passes uncounted, in
enforce it is refused. Alternative: on the switch to enforce, delete the conntrack entries of the work user's
connections. Open because `tests/test_egress.py` pins the current line and only a host with nft can prove the
rules; the owner decides on the replaced test.
Done that way: the `c_allowed` rules set `ct mark 0xa0b001`; the chain work accepts `established,related` only with
that mark and sends every other established or related packet to the chain refused uncounted (it passes in count and
is refused in enforce). The chain refused marks what it sees `0xa0b002` and `awb egress enforce` deletes those
conntrack entries (`conntrack -D -m 0xa0b002`, IPv4 and IPv6) after the switch; without conntrack the switch stands,
says so and the entries stay until they time out while the filter refuses their packets. The owner allowed on
2026-10-13 that EG-6 (`test_the_rendered_rules_count_or_refuse_by_mode_for_ipv4_and_ipv6`), which pinned the old
line, is replaced by `tests/test_egress.py::test_the_rendered_rules_mark_what_they_allow_and_pass_established_only_with_the_mark`.
Tests: `::test_a_connection_opened_outside_the_list_in_count_does_not_survive_enforce`,
`::test_enforce_deletes_the_conntrack_entries_of_the_work_users_connections_outside_the_list`,
`::test_enforce_without_conntrack_still_switches_and_says_the_filter_refuses_the_old_connections`,
`::test_a_refused_or_failed_enforce_deletes_no_conntrack_entry` and
`::test_verify_checks_that_an_established_connection_passes_only_with_the_mark`. `seal/verify.sh` reads the two lines
from the loaded chain; it does not try a connection across the switch, which needs a peer outside loopback and a
change of the host's mode. Only a host with nft proves the rules live (`nft -c` checks them where it may run).

### B1, medium-high: the handover and rebase units ran the task's git configuration with write access to every clone (fixed, a4cc454)

`unit_run` gave every helper unit `rw=[wt/, home/]` and hid only `runs/` and the login paths, without a network
namespace. The handover runs `git status` and more in the task's clone through `_hgit`, which overrode only
`core.fsmonitor` and `core.hooksPath`. The session can write its clone's `.git`: `filter.x.clean` with `* filter=x` in
`.git/info/attributes` (or `gpg.program` with `commit.gpgSign` for the rebase) ran its command in the helper unit as
`awb-build`, which can read and change the clones and homes of other tasks, plant names in `wt/` (B2) and
pre-create the clones of later runs. Fix: the handover and rebase units get `rw=[clone, out]`,
`hidden=_hidden(host, ctx)` with the login paths and `netns=True`; only the prepare and clean units keep `wt/` and
`home/`. Before git runs there, `_clone_ok` refuses (exit 4) a `.git` that is a link or a gitfile, one that holds
`commondir`, `config.worktree` or `info/attributes`, and a `.git/config` (read without includes) with a key outside
a fixed list; `_hgit` runs git with fixed overrides (`core.fsmonitor`, `core.hooksPath`, `core.attributesFile`,
`commit.gpgSign`, `tag.gpgSign`) beside `GIT_CONFIG_NOSYSTEM` and the root template as `GIT_CONFIG_GLOBAL`. The
config is checked, not rewritten: a rewrite would hide the selftest case `n11-fsmonitor`. Tests:
`tests/test_build_runner.py::test_the_handover_and_rebase_units_write_their_clone_alone_and_have_no_network` and
`::test_a_helper_unit_refuses_a_clone_whose_git_would_run_a_command_of_the_session`. Still to prove on the host: the
handover and the rebase need no path beyond the clone, the out folder and the readable root template.

### E2, medium: an inbound connection to a listener of the work user passed in enforce (fixed, 06947a7)

The same `established,related accept`: a session runs `python3 -m http.server`, an outside party connects in and the
work user's replies are established. Nothing filters input; whether it works depends on the security group. Fix: the
mark of E1 closes it (an inbound connection is never marked); an input chain that drops new inbound connections to the
work user's ports would add depth.
Done that way: the mark of E1, no input chain. The table hooks the output alone and nft gives the SYN-ACK of a
listener the listener's uid, so the SYN-ACK and every later answer are established packets without the mark and are
refused in enforce. An input rule cannot tell the work user's listener from another before the socket lookup. Left
as a limit in `seal/egress/ALLOW.md`: a packet from outside still reaches the listener (with SYN cookies under a flood
the SYN-ACK carries no socket and a handshake can complete); nothing the listener sends back leaves the host. Test:
`tests/test_egress.py::test_an_inbound_connection_to_a_listener_of_the_work_user_never_answers_in_enforce`.

### M1, medium: a deeply nested JSON line ended the MCP server (fixed, 2a0351d)

`serve()` caught `ValueError` and `UnicodeDecodeError` around `json.loads`, not `RecursionError`. A line of
200000 `[` and as many `]` raised `RecursionError` in the parser and ended the server with a traceback; every
later request of the client got no answer. The server ships to strangers and must stand any malformed JSON-RPC.
Fix: `RecursionError` is a parse error (-32700) and the server goes on. Test:
`tests/test_mcp.py::test_a_deeply_nested_message_is_a_parse_error_and_the_server_goes_on`.

### X2, medium: the key service read an answer of any size (fixed, c0eef48)

`cloud.Client.request` read `resp.read()` and `exc.read()` whole; the key service masks the answer only after that.
A work session can run `awb cloud call GET obs /tcp-xxxx-.../big.bin` on an object of many GB in a project bucket
(or any bucket, see K1): the owner's key service holds it whole in memory and the OOM killer can end it, which locks
its keys. Fix: an answer is read up to `MAX_READ` (16 MiB), a larger one is cut, `data` is None and the command says
it was larger than the bound. Test: `tests/test_cloud.py::test_an_answer_is_read_up_to_its_bound_and_marked_cut`.

### B2, medium: names of `wt/` went unquoted into `InaccessiblePaths=` (fixed, 2e5ebec)

`_hidden` listed every name of `wt/` and `SystemdUnits.argv` joined them with blanks. systemd splits that list on
blanks and quotes. A folder `A"` and a folder `Z"` join every clone between them into one path that does not exist
(the `-` prefix makes systemd skip it), so the clones and exports of other tasks are no longer hidden; a name with a
blank adds a path of its choice. A task reaches `wt/` through B1. Fix: only names the runner makes
(`B-NNN-N`, `B-NNN-N.out`) are listed. Test:
`tests/test_build_runner.py::test_a_folder_in_wt_with_a_name_the_runner_never_makes_never_reaches_a_unit_property`.
Left open with it: the other paths of the unit properties are the runner's own and carry no blank; quoting every path
would be the general fix; it changes the fixed form that `test_the_real_spawn_is_one_fixed_form...` pins.

### B3, medium: the owner's runner read whole blobs (fixed, 2a202f6)

`scan_commits` (`git cat-file blob`), `show`, `commit_fields` and `_hunks` read with `capture_output`; the runner's
unit has no `MemoryMax`. A blob of tens of GB of zeros compresses about 1000 to 1 and fits under `BUNDLE_MAX`; check
6 runs before the path check 7. The owner's runner buffers it and the OOM killer may take the vault daemon or the
key service. Fix: `git cat-file --batch-check` over every changed blob first and red above a bound (16 MB), the same
bound on a commit message plus `MemoryMax=` in `seal/awb-buildd.service`.
Done that way: `oversized` sizes the commit objects and every blob they add or change with one `git cat-file
--batch-check` at the end of check 4; above `BLOB_MAX` (16 MB) the run is `red: message too big` or `red: blob too
big` and no later check reads it. `push_main` refuses such a range. `MemoryMax=2G` (a normal run peaks well under 1G,
the sessions and the suite run in units of their own). Test:
`tests/test_build_runner.py::test_a_blob_or_message_above_the_bound_is_red_before_any_read_and_main_stays` and
`::test_the_runner_unit_has_a_memory_limit_that_fits_the_fetch_of_a_full_bundle`.

### B4, medium: the session unit reached the upstream resolvers on every port (fixed, 9307d79)

`IPAddressAllow=` takes addresses, not ports, so the resolvers of `model_allow` are open on every port and protocol.
A task can tunnel through DNS (the copied login, the model key, the clone) and, where the resolver is the metadata
address (169.254.169.254 on some clouds), reach the metadata API. Fix: the runner resolves the model and token hosts
as now, binds a hosts file over `/etc/hosts`, gives the unit a `resolv.conf` without a nameserver and leaves the
resolvers out of the allow list; the probe and `verify.sh` follow.
Done that way: `model_allow` returns the allow list (the endpoints' addresses alone) and the names with their
addresses from one resolution; `name_binds` writes the hosts file (loopback and those names) and a `resolv.conf`
without a nameserver into the run folder and binds them over `/etc/hosts` and `/etc/resolv.conf` for the session and
every probe unit. The probe's hosts file also names the TCP API host and GitHub, never allowed, so their refusal stays
the address filter. The probe units of `verify.sh` bind a hosts file of loopback and a `resolv.conf` without a
nameserver. A host without an upstream nameserver still holds the queue. Tests:
`tests/test_build_runner.py::test_the_session_unit_binds_a_hosts_file_and_a_resolv_conf_without_a_nameserver`,
`::test_the_allow_list_names_the_endpoints_alone_and_never_a_nameserver`,
`::test_the_probe_binds_a_hosts_file_and_never_allows_a_nameserver` and
`tests/test_seal.py::test_the_probe_units_of_verify_bind_a_hosts_file_and_a_resolv_conf_without_a_nameserver`.
Left open with it: the varlink and D-Bus sockets of systemd-resolved stay visible to the unit; with `nss-resolve` in
`nsswitch.conf` a unit could still ask the host's resolver through them.

### X1, low-medium: an OBS answer with a DOCTYPE was parsed (fixed, 6c04513)

`xml_result` parses every successful answer that is not JSON and starts with `<`, so a GET of an object whose body
is XML is parsed in the owner's key service. ElementTree resolves no external entity. Expat 2.6 (the venv here
has 2.6.1) caps the billion-laughs growth, but internal entities still grow a few bytes up to the cap (about 100
times the input past 8 MiB). No OBS answer carries a DOCTYPE. Fix: a body that declares a DOCTYPE or an entity is
never parsed: `xml_result` gives None, `xml_error` empty strings, `Client.list` refuses it. Tests:
`tests/test_obs.py::test_an_obs_answer_with_a_doctype_is_never_parsed` and `::test_a_listing_with_a_doctype_is_refused`.

### B6, low: the export applied in-tree filter, ident and eol attributes (fixed, 1b9a277)

`export` runs `git archive` in `main.git` as the owner with his own `~/.gitconfig`. `info/attributes` switched only
`export-ignore` and `export-subst` off. A task's `awb/.gitattributes` with `* filter=NAME` turns on a filter that the
owner's configuration defines (git-lfs for one) and runs it as the owner; `ident` and `eol` make the export differ
from the blobs the gate scanned. Fix: `info/attributes` also switches `filter`, `ident`, `text`, `eol` and
`working-tree-encoding` off. Test: `tests/test_build_runner.py::test_the_export_runs_no_filter_and_keeps_the_blobs_the_gate_read`.

### E3, low-medium: a removed table goes unnoticed (fixed, 9ed5f30)

`systemctl restart nftables` (whose default file starts with `flush ruleset`) removes the table. The next `load`
loads it again and records nothing: in count the window reads covered while connections went uncounted, in enforce
the status shows no gap of up to 5 minutes. Fix: keep the boot id in `status.json`; a table missing within the same
boot restarts `count_since` and the status says so.

Fixed: `status.json` keeps `boot_id`. A table missing at `load` within the boot of the last load sets `table_lost_at` and restarts `count_since`; `awb egress status` shows a line about it. After a reboot the load stays a plain load. Tests: `tests/test_egress.py::test_a_table_missing_within_the_same_boot_restarts_the_count_and_the_status_says_so` and `::test_a_table_missing_after_a_reboot_is_a_plain_load` (they skip as root, like the other tests with the `world` fixture).

### X3, low: a listing that repeats its marker loops forever (fixed, ebe936a)

`obs.Client.list` follows `NextMarker` (or the last key) while `IsTruncated` is true, with no bound and no check that
the marker moves. An answer that repeats itself keeps the caller in the loop. Fix: stop with an error when the marker
does not move or after a page bound.

Fixed: `Client.list` stops with an `OBSError` when the next marker was seen before, and after `MAX_PAGES` (100000) pages. Tests: `tests/test_obs.py::test_a_listing_that_repeats_its_marker_stops_with_an_error` and `::test_a_listing_past_the_page_bound_stops_with_an_error`.

### M2, low: the MCP server reads a line of any length (fixed, e2864f2)

`for raw in stdin` holds a whole line; the client is the user's own, so this is a self-inflicted exhaustion. Fix: read
with a bound (`readline(LIMIT + 1)`), answer a longer line with a parse error and skip to its end.

Fixed: `serve` reads with `readline(MAX_LINE + 1)` (8 MiB), answers a longer line with a parse error (-32700) and skips to its end without holding it. Test: `tests/test_mcp.py::test_a_line_over_the_bound_is_a_parse_error_and_the_server_goes_on`.

### M3, low: `--live` reads the price API answer whole (fixed, d318276)

`_live` reads `r.read()` from the fixed price host; only with `--live`. Fix: read up to a bound.

Fixed: `_live` reads at most 32 MiB (`MAX_PRICE_ANSWER`) and gives no live rows for a longer answer, so the tool falls back to the snapshot. Test: `tests/test_mcp.py::test_live_reads_the_price_answer_up_to_a_bound`.

## Open

### T1, medium: nothing keeps the tests off the real network

The audit hook skips a `socket.connect` whose address is a tuple. Without `AWB_CLOUD_ENDPOINT` the key service and
cloud code fall back to the real endpoints; the Ask page posts to the model API. Fix: refuse a connect or
`getaddrinfo` to any host that is not loopback while a test runs. Open because it may touch many tests and needs a
full run of the suite on its own.

### T2, medium: `AWB_*` variables of the owner's shell reach the tests

The fixture sets about 20 variables and clears none of the others: `AWB_CLOUD_KEYS`, `AWB_BUCKET_KEYS`,
`AWB_BUCKET_ENDPOINT`, `AWB_CLOUD_ENDPOINT`, `AWB_ASK_KEY_FILE` and more. With `AWB_BUCKET_KEYS=pass:ENTRY` exported, a
test that sets no endpoint runs `pass show` on the real password store and reaches the real OBS. Fix: delete every
`AWB_*` variable at the start of the fixture, then set the invented ones; put a `pass` that exits 1 first on `PATH`.

### T3, medium-low: the real home and key socket under a patched `is_work_user`

19 tests patch `config.is_work_user` to True; `config.paths()` then ignores the environment and takes the real
`~/tcp-shared` and `~/tcp-kb`; the hooks take `/run/awb-keys/cloud.sock`. None of these is guarded. Fix: set `HOME`
to a folder of the test and add the `/run/awb-*` sockets to the guarded ones.
Owner decision T3H-a (dcc42a6): `HOME` is not moved, since the repository and its `.venv` live under the real home and
the spawned projects then carried absolute home paths. The guard refuses the real `~/tcp-shared` and `~/tcp-kb` instead.

### B5, low-medium: shared `/dev/shm`, `/dev/mqueue` and `/tmp` on the root filesystem

`ProtectSystem=strict` leaves `/dev` writable and there is no `PrivateIPC`: files in `/dev/shm` and `/dev/mqueue`
outlive the unit (a channel between tasks, memory that adds up). `PrivateTmp` puts `/tmp` on the root filesystem, so a
task can fill the filesystem of the vault. The helper units share the host network namespace (abstract sockets).
Fix: `PrivateIPC=yes`, `TemporaryFileSystem=/dev/shm:size=64M`, `/tmp` and `/var/tmp` with a size, `ProtectProc=invisible`,
`ProtectKernelTunables=yes`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX` for the session and `PrivateNetwork`
for the helper units.

### B7, low: a task can replace the build user's login

`_login_back` takes the login file of the task home back when it looks newer. A task writes one with a far-future
`expiresAt`: the build user's real login and refresh token are gone; or later tasks run on an account the task chose.
Fix: refuse an `expiresAt` beyond now and a bound and keep the previous file.

### K1, low: an OBS read reaches the buckets of any project

`keys.py` refuses the exchange buckets and keeps a write on the project's buckets, but a read (`GET`, `HEAD`) reaches
every bucket of the tenant, those of other projects included. Fix, if wanted: a read too reaches only `/`, the
buckets of the project and the buckets a setting names.

### T4, low: module fixtures and import-time code run before the guard

Both autouse fixtures are function-scoped: a module fixture (`scan` of `tests/test_self_clean.py`) runs with the real
host file and blocklists. Fix: switch the guard and the environment on in a session-scoped fixture or in
`pytest_configure`.

### T5, low: a link made before the test hides the vault from the guard

`_vault_hit` normalises a path and does not follow links; a link into the vault made before the run is not seen
(one made during the test is). Fix: check `os.path.realpath` too.

### D1, note: a task's tests can forge their own green

Checks 9 to 11 run the task's test code; code that runs when pytest imports a module can patch pytest or rewrite
`out/suite.xml` before the unit ends. Green is no proof of integrity. The push to GitHub follows, checked by the
gate (names and secrets) alone. What reaches a deploy depends on the owner's review.

## Checked and found sound

- The egress rendering: the work user, every address and every row of `ALLOW.md` are validated before they reach
  the nft text; empty sets give no syntax error and leave the allow set empty; the load is one atomic `nft -f`; both
  families are covered; `meta skuid` holds through user namespaces; root writes its state by `mkstemp` and
  `os.replace` in a root folder; the mode comes from the root host file alone.
- The runner's own git works only in `main.git` with hooks and fsmonitor off and `fsckObjects` on; the fetch takes
  `refs/heads/*` into a quarantine with `--no-tags`; no branch name reaches an argument list.
- Task ids, run numbers and unit names are checked by pattern; the `systemd-run` argument list is fixed and ends
  with `--`; `_take` reads the build user's files without following a link, with owner, link count and size checked.
- The push fetches origin, checks that `main` descends from it, gates `origin..main` with the register and never
  forces.
- The key service passes no header of the request to OBS, so `x-obs-copy-source` cannot name an exchange bucket.
- The MCP server's file paths are resolved and checked against the dataset folder; the region is an enum; the
  calculator bounds its length, nodes, exponent and magnitude.
