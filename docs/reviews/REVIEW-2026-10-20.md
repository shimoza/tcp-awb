# Attacker review of 2026-10-20 (PRs 40 to 64)

Scope: what was merged into main from PR 40 to PR 64 (`git log --merges --oneline 3f100c1..HEAD`). The attacker is a
hijacked work session (uid `awb`), a hostile pull request (a build task, uid `awb-build`), a hostile file in an inbox
or a hostile release note page. The review read the code and changed none. It ran no systemd unit, no nft, no sudo
and no root step: a finding about those is read from the code, the unit files and the documented grammar and says so.
Line numbers are those of 00f0c98. The K1 of the review of 2026-10-13 is called "old K1" here.

## Findings

**K1, high (code).** `clone_dir` is `<shared>/datasets/tcp-facts.git` (`dataset.py:933`, `kbreview.py:51`), in the
work user's tree. `_git` (938) adds `safe.directory` for it, so the clone's own `.git/config` and hooks are trusted;
`put` runs `pull` (1069), `add`, `commit` and since PR 56 `tag -s` with `user.signingkey` (1101). Attack: a session
sets `core.hooksPath`, `core.fsmonitor` or `gpg.ssh.program` in that clone (or swaps the clone). Effect: code runs as
the owner on the next `awb dataset put --github` and reads the signing key. Fix: keep the clone on the owner side;
until then run git with `-c core.hooksPath=/dev/null -c core.fsmonitor=false -c gpg.ssh.program=ssh-keygen` and
refuse a `.git` the owner does not own.

**K2, medium (code).** The mark `tcp-facts-D.review.json` and `RELEASED.jsonl` lie in `<shared>/datasets`
(`dataset.py:687`, `kbreview.py:155`). `require_review` (`kbreview.py:160-176`) checks `facts_sha256` and `since`,
never the writer; `awb kb review` has no work user refusal. Attack: a session poisons the kb, builds and reviews
itself or rewrites `RELEASED.jsonl` so the owner's review shows nothing new. Effect: `put` (`dataset.py:1175`)
releases facts the owner never read; G6 is void. Fix: `put` shows the changes on the owner's terminal and asks, or
mark and baseline live on the owner side; refuse `awb kb review` for the work user.

**K3, medium (code).** `_sign_sums` (`dataset.py:1047`) hashes the zip, `HOW-TO.pdf`, `MANIFEST.json` and the
`.mcpb` (a server readers run) as they are now; the review pins only `facts.jsonl`. `write_text` follows a planted
`SHA256SUMS` link. Effect: the owner's key vouches for files a session changed after the review and the owner
overwrites a file of the link's choice. Fix: record every asset's hash in the review and compare before signing;
write the sums with `O_NOFOLLOW|O_EXCL`; `ssh-keygen -Y verify` after signing.

**K4, medium (code or host).** `keys.py:840` `project = req.get("project")`; 848-857 check only that it is active
and granted; `_obs_read_ok` (915) allows `bucket.startswith(project + "-")`. Every session is uid `awb`. Attack: a
session of `tcp-aaaa` sends `"project": "tcp-bbbb"`. Effect: it reads the buckets of any granted active project; old
K1 is narrowed, not closed. Fix: bind the project to the caller (session lock and peer pid's folder) or a uid per
project. Else record the limit.

**K5, medium (code).** `StatusHandler` (`gateway.py:1535`) has no `timeout`; the socket is 0666 (1609,
`seal/web/awb-web-status.socket:10`); its threads share the gateway's `TasksMax=128`. Attack: any local uid opens 130
idle connections. Effect: the site stops; `awb web status` and the deploy probe time out. Fix: `timeout = 3`.

**K6, medium (code).** `mirror.py:307-309` takes `last_page` from any `?p=N` link; 408 loops to it and
`refresh.py:217` passes no `pages`; 379 `resp.read()` has no cap and the 30 second timeout is per read; titles have
no cap. Attack: `?p=999999` with fresh notes on every page or a huge or trickled body. Effect: the owner's refresh and
`awb mirror rn` run without end and fill memory and `~/tcp-mirrors`. Fix: clamp `last`, cap pages, `read(MAX + 1)`,
cap fields, a total deadline.

**K7, medium (host).** `setup.sh:498` joins tools as `/usr/bin/pdftotext *, /usr/bin/pdfinfo *` after one prefix
(506). In sudoers a comma separates commands, so the second is bare `pdfinfo` as root with no unit and the unit's own
`pdfinfo` call matches nothing (every PDF fails closed at `pdf.py:291`). Read from the sudoers grammar, not run.
Effect: an owner-uid process plus a poppler bug is root; the sandbox never works. Fix: repeat the prefix per tool;
add a `pdfinfo` probe to `verify.sh`.

**K8, medium (code).** `LOGIN_ACCOUNT = "subscriptionType"` (`build_unit_side.py:38`) is a plan tier every account
of that plan shares; 191-197 need only the same tier and a later `expiresAt`, with no upper bound, then write the
task's bytes whole (207). Attack: a task writes its own account's login with `expiresAt` far ahead. Effect: later
tasks run on the attacker's account, no real refresh is copied back again, extra keys travel between tasks (B5).
Fix: copy back only the token fields into the old object, bound `expiresAt`, compare the account id.

**K9, medium-low (code).** `keys.py:925` `path.startswith(p)` over pairs cut at the first `${`
(`labwrites.py:17`); 922 allows all when `lab_writes` is missing; no method, no query check. With the current
recipes `ecs:/v1/{project_id}/cloudservers` passes every ECS v1 write and `obs:/` every OBS write; leases
(`lease_policy`, 938-953) never meet the list. Fix: `METHOD service path` triples matched whole, refuse without the line.

**K10, low-medium (code).** `projects.py:980` keeps ESC; `awb` without arguments (`cli.py:292`), the `awb close`
refusal and `live_resource_lines` print it raw. A session writes `- owner: ESC]52;...` to OPEN.md, uncommitted so no
gate. Effect: clipboard write or a forged line on the owner's terminal. Fix: drop Cc and Cf as `build.py:982` does.

**K11, low-medium (code).** `writing.py:1764` reads a linked DRAFT; the folder check (2133-2142) is skipped with
`--project`; the copy lands in `<shared>/voice/pairs`; `_mkdir` (1736) follows planted links. Effect: an owner file's
text lands where a session reads it or an owner folder is chmodded 0750. Fix: `O_NOFOLLOW`, real path inside the
project always, `config.make_dir(..., shared=True)`.

**K12, low-medium (code).** `int()` of over 4300 digits (`mirror.py:309`) raises `ValueError`; a cut body raises
`http.client.HTTPException` (379). Neither 412-416 nor `refresh.py:612` catch them. Effect: no `REPORT.md`, all parts
lost for the day. Fix: `\d{1,6}`, map both to `MirrorError`.

**K13, low-medium (code).** `refresh.py:190` writes any tag and h2 text into `REPORT*.md` and `release-notes.txt`
under `<shared>/refresh/` (241, 244); only whitespace is collapsed, ESC and C1 stay; `new service?` lines have no
cap. Effect: prompt text for sessions, escapes for the owner. Fix: print the note id only or vet as printable ASCII.

**K14, low (code).** `cli.py:404-409` suggests `--customer X` with `X` from the row a session writes; an owner who
copies it confirms the session's value. Fix: show it, ask the owner to type the code from the register.

**K15, low (code).** `hooks.py:1150` mails as the work user; the admin socket refuses that uid (`keys.py:582`), so
the mail never goes out. Fixed naively, `item_command` (`projects.py:724`) would mail any `awb SUB ARGS` the session
wrote, unchecked for names. Fix: send from an owner process, an allow list of commands, a name check.

**K16, low (host).** `_load_fingerprint` (`review.py:1646-1666`) accepts an empty list from the shared side and the
gate trusts it for a closed project (1848-1856). A session empties `fingerprints/tcp-B.json` and B's deliverable
passes the cross-project check. Fix: pin the fingerprint's hash on the owner side at close.

**K17, low (code).** `gateway.py:910` sets a socket timeout; headers and `rfile.read` (968, 996) wait 5 seconds per
byte, not in total. Limited: only cloudflared reaches the front socket. Fix: a monotonic deadline.

**K18, low (code).** `pdf.py:161` reads unit stdout through `PIPE` uncapped; `MemoryMax` bounds the unit, not the
intake. A crafted PDF emits gigabytes within 120 seconds. Fix: read in chunks with a cap.

**K19, low (code).** `pdf.py:168-170` runs direct when `extract_user` is empty and `host_conf()` returns `{}` on any
`OSError` (`config.py:210-214`). Fix: run direct only when the host file was read and says so.

**K20, low (code and host).** `UNIT_PROPERTIES` (`pdf.py:134`) has no `PrivateIPC`, own `/dev/shm`, `ProtectProc`,
`RestrictAddressFamilies` or `PrivateDevices` and has a fixed uid. Fix: add them, `DynamicUser=yes`, widen sudoers.

**K21, low (code).** `SHM_FS = "/dev/shm:size=64M"` (`build_units.py:70`) mounts root-owned 0755 by systemd's default,
so a task cannot use POSIX shm (read from systemd.exec). Fix: `size=64M,mode=1777,nosuid,nodev`.

**K22, low (code).** `json.loads` (`build_unit_side.py:160`) of 64K `[` raises `RecursionError`; 408 suppresses only
`OSError`, so the clean unit dies before `rmtree` and the home with the login stays. Fix: catch it; check the exit code.

**K23, low (code).** `mirror.py:369` `\d` accepts Arabic-Indic digits; the date sorts after today and passes the
first-run floor (`refresh.py:182,232`). Fix: `[0-9]` and `date.fromisoformat`.

**K24, low (code).** `mirror.py:378` follows redirects to any http or https host, 169.254.169.254 included: a blind
request from the owner's machine for the site's owner. Fix: same host https only or no redirects.

## Checked and found sound

- `cli.py:_cmd_unlock`: refused for the work user, getpass only, admin sockets admit the owner uid only.
  `status_lines`: states matched against fixed words.
- `cli.py:_cmd_close`, `projects.close`: the code passes `is_project_code`, the folder comes from the register.
- `register.py:find_code`: exact compare, no regex, prints code and kind; refused for the work user, in a session and
  without a tty. `add_forms`: all or nothing. `importcmd.py:ask_forms`: fixed text plus a code.
- `intake_counts.py:record_intake`: the extractor value is allow-listed.
- `writing.py:learn_owner`: refused for the work user, in a session and for a tty; `mkdtemp` removed in `finally`.
- `gateway.py:address_key`, `client_key`, `Auth.hold`: IPv6 by /64; CF-Connecting-IP only on a peer-uid listener;
  count and semaphore under one lock. `route` (G10) cuts every `/api/projects/CODE/...` route per reader.
- `publish.py:_ask_socket`: bound by systemd in root-owned `/run`. `ask.py`: escaped values, strict CSP, Origin check.
- Portal removal: `setup.sh:retire_portal_unit` removes the unit and its drop-in; nothing else names it.
- `seal/egress/ask-egress.nft`: `meta skuid` in an inet table; established only with mark 0xa0b003; enforce ends in
  `reject`; two hosts on 443. In mode count (the default) the Ask uid has full egress, as `ALLOW.md` says.
- `keys.py:_obs_read_ok`: bucket parsed as in `cloud.obs_call`; fixed-width codes; exchange buckets refused first.
- Grant: `^CUST-[A-Z2-7]{4}$`, `awb start` passes the owner's code, `_customer_differs` refuses a lease on mismatch.
- `build_units.py:SystemdUnits.argv`: `PrivateIPC=yes`, `/dev/mqueue` inaccessible, names only from the runner.
- `build_unit_side.py:_read_login`, `_login_back`: `O_NOFOLLOW` per step, regular file, uid check, 64K cap, temp file
  with `O_EXCL` then `os.replace`, bytes read once.
- `buildrun.py:push_main` (deployed): the target is root's `DEPLOYED`, a SHA with ancestor checks; the gate runs over
  exactly `remote..top`; no ref name comes from the task.
- `pdf.py:UnitRunner`: the file goes on stdin as `-`; direct mode passes an absolute path; a failed unit never falls
  back to direct.
- Release notes: stdlib `HTMLParser`, no entity expansion, linear regexes, no gzip; page hrefs are never fetched; the
  note link check is exact host and https; file names fullmatch `[a-z0-9][a-z0-9._-]{0,150}` after the date; writes go
  by temp file and `os.replace`; the fetch runs on the owner side only; kb, TCP Facts and the dataset do not read
  release notes. PR 64 narrows only which kb entries are listed per note.
