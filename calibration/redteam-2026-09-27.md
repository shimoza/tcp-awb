# Red team of the intake and the gate, 2026-09-27

Eight finders on Fable 5.1, one per dimension, each in a loop against a harness that builds a case, runs it
through a throw-away Workbench with the invented register of `tests/fixtures.py` and says caught, escaped
(with the reader's view that read the value: raw, case, skeleton, leet, reversed, decoded, whole word) or
unseen (an innocent marker planted next to the value reached no output). Every claimed escape went to a
skeptic that re-ran the one case, opened the output and judged it by eye. The harness proved it can fail
before the run: a planted card number and an unregistered name after --force were reported as escapes.

Rule of the run: invented values only, nothing outside the scratch folder written, the repository read only
for the finders, no vault, no private folder of the owner, no value in any result. Cost: 125 agents, 1,188 cases, about
10.3 million subagent tokens, 40 to 60 minutes per dimension in parallel on the two CPUs of this host.

## What changed

The intake side (this session):

- `awb/patterns.py`, rewritten. Mail with the at and the dots spelled out or bracketed, quoted and non-ASCII
  local parts, an IPv6 literal, a break after the @. Hosts under every country code and the common generic
  names, defanged with `[.]` and `hxxp`, a wildcard or a leading dot; a file suffix that is also a domain
  (setup.py, main.tf, report.md) needs a host of two labels in front of it, and a short capitalised word with
  two letters behind a dot (Tel.Nr, Bsp.AG) is an abbreviation. IPv4 with zero padded or full width digits,
  inside a cloud host name (ip-a-b-c-d) and after "IP-Nr."; IPv6 with a label glued by a colon. MAC in Cisco
  dotted form, dashed groups of four, behind a label. IBAN with any separator, over a line break, letter by
  letter, in Markdown boxes and table cells, behind a glued label, cut at the length its country announces,
  so that a second IBAN right behind it is found too. BIC in lower case and in groups behind a label. VAT ids
  with spaces or a dash and for thirteen more countries. Phone numbers with the area code in parentheses,
  dots, pairs, two separators in a row, a line break, a trunk zero on its own, a full width plus, after "Tel."
  and after the slash between two numbers; dates and dotted quads are never numbers. HRB with a dash, "Nr.",
  lower case or "Handelsregister B"; tax numbers behind every spelling of the label and in the five-five
  shape. A view folds markup inside a value, per glyph spacing and the border between two table cells
  before matching, and reports the span at its place in the text.
- `awb/matcher.py`. Markup with line breaks, long attributes, CDATA, processing instructions and
  declarations is blanked; an address in angle brackets is not markup. A form of letters may start or end
  inside a run when the rest is digits (abc-de01) or, for a long form, a glued word (first|namestr). Four
  more look-alike letters; digits of every script fold to plain digits.
- `awb/normalize.py`. Numeric entities without a semicolon and with any digit count, RTF `\uN` escapes,
  `\x` escapes, a quoted printable soft break in a text that carries other QP marks, punycode labels,
  terminal colour sequences. `strip_invisible` removes bidi controls, zero width and tag characters and
  colour sequences.
- `awb/intake.py`. The sanitised output never carries a bidi override or a tag character, hit or no hit.
- `awb/extract/text.py`. A hex block that is mostly digits is text; a hex block that decodes to binary
  gives its strings to detection like a base64 one; `0x` and `\x` in front of a hex block are not part of
  it; a multi-line base64 block of binary is decoded from its joined lines; MIME style blocks start at 24
  characters per line and may carry a mail quote prefix; a spaced hex dump is a block; `noscript` text stays.
- `awb/extract/__init__.py`. A PDF header within the first 1024 bytes, svg as a kind of its own (text nodes
  read like html, the picture held on the vault side), HEIF, EMF and WMF as pictures.
- `awb/extract/pdf.py`. Embedded files and the documents of a portfolio are saved with pdfdetach and read as
  children; annotation contents and subjects, form field values, outline titles and scripts reach detection
  with a note.
- `awb/images.py`. Pictures of the kinds svg, heic, heif, avif, ico, emz and wmz are held.
- `awb/planted.py`: 79 more shapes, 180 in all, each one run before every intake.

Three agents in their own worktrees, merged afterwards:

- `awb/extract/office.py` (23 tests). Chart text, SmartArt, legacy WordArt, block equations, odt hidden and
  conditional text and ods shapes reach the output where they stand; alt chunks are read as children; slides,
  footnotes, endnotes, headers, footers, comments and shared strings are found through their relationships and
  under their fixed names only as a fallback; a repeated part name, a macro project and an embedded font give a
  note and mark the file incomplete; a binary property is decoded; eighteen carriers that were scanned for
  names only (content control items, table captions, numbering text, phonetic runs, number formats, validation
  texts, formatting formulas, hyperlink texts, cached external cells, legacy text boxes, pivot and query names,
  slicers, tags, section names, field declarations, form values) go to detection.
- `awb/extract/mail.py` and `archive.py` (16 tests). Raw cp1252 headers keep their umlauts; a wrong charset
  label is corrected both ways; utf-7 and quoted printable parts without a label are decoded; the preamble and
  the epilogue reach the output; a mailbox is split into its messages; a zip member with a trailing slash and
  data is a file; the raw name of a member with a unicode path field and the gzip header of a compressed tar
  reach detection; inline uuencode blocks become attachments.
- `awb/gate.py` (132 tests). Keys behind flags, inner assignments, passwords in URLs and headers, quoted and
  name-shaped values, the key words of every office, XML elements, values on the next line, credential files
  and tables, more token prefixes, keys without armour, key pairs two lines apart, home paths of every desktop,
  blocklist spellings with a variable in front, identifiers behind more labels; every detector over the raw,
  the normalised and the decoded text. New: `awb gate --message` with `hooks/commit-msg`; on push the ref names,
  tags, authors, committers and messages are scanned and a merge commit is diffed against each parent.

## Design limits kept on purpose

- A typo of a registered form standing alone, a first name alone, "Tobias B.", a lone acronym glued to a word
  that is no affix of `rules/glue-affixes.txt`, the year and number of a tender id without its prefix, a
  place with an ae spelling the register does not list: the register decides what a form is. Inside a
  candidate shape (a legal form, a title, a label, a run of capitalised words) every one of them blocks the
  run.
- A named entity without its semicolon (his decision of the normaliser test), quoted printable of ASCII
  text, an IBAN with a wrong check digit, a BIC of eight letters without a label or a digit, a MAC of twelve
  hex characters without a label, a tax number without a label, a country code without plus or 00, IPv4 in
  decimal or hex form, a vanity number with letters, leet spellings, base32, uuencode and BinHex in a plain
  text file, a phonetic spelling in another alphabet, bare hosts under a file suffix domain (.ai, .sh, .md).
- The second check withholds a whole output rather than sanitising it when only it sees a form (a file
  number without separators, an acronym spaced with dashes): safe, the file stays in the inbox with a note.
- Kinds no pattern claims: card numbers, a Steuer-ID without a label, social security and id card numbers,
  license plates, account number and bank code, coordinates, dates of birth, platform ids (32 hex, UUID),
  access key pairs, tokens, passwords and private keys in customer material. Listed for his decision.

## Open after this run

- Pictures inside containers (a jpg in a zip, an attachment of a mail) are noted but not held; the picture
  metadata of a held file is never scanned.
- A PDF whose font maps glyphs to other letters shows a name the text layer does not carry; a page rendered
  as a picture would be the only way to review it.
- The two-row split of a value in a sheet (an IBAN typed over two rows) is not read as one value.
- The harness cannot see a three letter value inside a longer word, and its decoded view reads base64 and
  hex line by line; the finders verified such cases by hand.

## The pack

The case files of the run live in `calibration/redteam/` (its README.md says how to read the lines): the two
harnesses, one module per dimension (structured, forms, derived, office, pdf, mail_archive, nontext, gate), the
brief and `EXPECTED.md`, the leftovers per dimension after this run. Every registered form comes from
`tests/fixtures.py`, every planted secret, key, path or id is built from pieces, so the commit gate prints nothing
over the pack. `tests/test_redteam_pack.py` checks the modules and runs a sample; the full runs are these commands,
one per dimension, from the repository root (a work folder outside the repository):

```bash
.venv/bin/python calibration/redteam/harness.py calibration/redteam/structured.py --work /tmp/rt/structured --json /tmp/rt/structured.json --expected calibration/redteam/EXPECTED.md
.venv/bin/python calibration/redteam/harness.py calibration/redteam/forms.py --work /tmp/rt/forms --json /tmp/rt/forms.json --expected calibration/redteam/EXPECTED.md
.venv/bin/python calibration/redteam/harness.py calibration/redteam/derived.py --work /tmp/rt/derived --json /tmp/rt/derived.json --expected calibration/redteam/EXPECTED.md
.venv/bin/python calibration/redteam/harness.py calibration/redteam/office.py --work /tmp/rt/office --json /tmp/rt/office.json --expected calibration/redteam/EXPECTED.md
.venv/bin/python calibration/redteam/harness.py calibration/redteam/pdf.py --work /tmp/rt/pdf --json /tmp/rt/pdf.json --expected calibration/redteam/EXPECTED.md
.venv/bin/python calibration/redteam/harness.py calibration/redteam/mail_archive.py --work /tmp/rt/mail_archive --json /tmp/rt/mail_archive.json --expected calibration/redteam/EXPECTED.md
.venv/bin/python calibration/redteam/harness.py calibration/redteam/nontext.py --work /tmp/rt/nontext --json /tmp/rt/nontext.json --expected calibration/redteam/EXPECTED.md
.venv/bin/python calibration/redteam/gate_harness.py calibration/redteam/gate.py --json /tmp/rt/gate.json --expected calibration/redteam/EXPECTED.md
```

With `--expected` a run names every leftover that is new (exit 1) and every listed id that is clean now.

The curation of the pack ran every dimension again against the merged code and found two things the run had not
named:

- A registered form followed by a space or a line break and a word that starts with `s` loses that letter in
  the sanitised output (`Kunde CUST-Q7M4tage two` for `... GmbH` and `stage two`). The genitive variant of the
  form (`GmbHs`) is matched across the separator and the rule that lets a long form end inside a glued word
  takes the `s` of the next word. It is not a leak, it damages the text a session reads. Fixed the same
  evening: the glued-word rule asks for three characters of the key inside the run. The harness reports such a
  case as `clipped`; `EXPECTED.md` lists the ones seen before the fix apart from the leftovers by design.
- The national phone pattern (`awb/patterns.py`, the third PHONE entry: `0\d{1,5}` then up to twelve groups of
  `\d{1,5}` with an optional separator between them) backtracks exponentially on a long run of digits that ends
  in a letter. One hundred hex characters take over five seconds, the hex of an embedded object in an rtf does
  not finish. An rtf with an embedded picture or object, a hex dump or a long id in a text file stalled the
  intake. Fixed the same evening with possessive digit groups (the third run below found it again from the
  prompt side); the four nontext cases run again and are listed under unseen like the other binary carriers.
