# Presidio as a second opinion on the wipe (task PP, 2026-10-27)

Question: does the open source analyzer Presidio (MIT, runs locally) find what `awb clean --kind docs` misses in
the 405 cases of the wipe red team, and what does it destroy?

Harness: `calibration/redteam/wipe/presidio_compare.py`. It builds every case as `clean_compare.py` does (a
throw-away laptop folder, the invented register of `tests/fixtures.py`, `clean.run(..., kind="docs")`) and reads
leaks and losses with the same readers' views (`calibration/redteam/harness.py`). Presidio is imported only inside
the harness and ran from a scratch environment outside the repository. Nothing under `awb/` changed.

Three readings per case:

- ours: the docs copy, its name and the report.
- Presidio alone: the text the `awb/extract` readers give for the original file (every part, as the docs copy
  writes them) and the file name, each detected span replaced by its entity type. No register.
- ours + Presidio: Presidio as a second pass over our copy and its name. The report stays as written.

## Setup and cost

- presidio-analyzer 2.2.365, presidio-anonymizer 2.2.365, spaCy 3.8.18, thinc 8.3.14, numpy 2.4.6.
- Models: en_core_web_lg 3.8.0 and de_core_news_lg 3.8.0. Russian has no model in this setup.
- Installed size: Presidio with its dependencies 373 MB, the English model 425 MB, the German model 610 MB. In all
  about 1.4 GB on top of the test packages.
- Model load: 4.4 s and 0.76 GB memory for English, 8.1 s and 1.6 GB for English plus German.
- Analyzer time per text: 17 ms with English, 39 ms with English plus German (1620 calls). Ours takes 0.76 s per
  case on the same host (most of it the throw-away laptop and the self-test), the second pass adds 0.085 s per case
  on average and 0.51 s at most.
- German: the default registry is English only. The harness loads the spaCy recognizer for both languages and adds
  the pattern recognizers (mail, phone, IBAN, URL, IP and the rest) again under "de". Every text is analyzed in both
  languages and the spans are joined, since a second opinion on the laptop cannot know the language of a file.

## Our 7 leaks

| case | ours + Presidio | entity type that closed it |
| --- | --- | --- |
| tf-acr-vm-glued-hostname (code_files) | clean | ORGANIZATION |
| de-lone-after-preposition (german) | leak closed, a new loss | PERSON, LOCATION, ORGANIZATION |
| ru-customer-translit-short-alone (russian) | leak closed, a new loss | PERSON |
| tf-resource-label-lower-surname (code_files) | still a leak, plus a loss | none |
| tf-comment-lower-surname (code_files) | still a leak | none |
| py-module-path-brand-surname (code_files) | still a leak | none |
| de-surname-klein (german) | still a leak | none |

The four that stay open are lower-case surnames in code, a brand glued into a module path and a German surname that
is also an ordinary word. A statistical name model reads none of them, because it relies on capitals and sentence
context. With only PERSON, mail and phone the Russian case comes out fully clean, the German one still loses a term
and the glued host name stays a leak. English alone closes only the German case.

Our 7 losses stay losses in every setting: Presidio never restores a term, it can only remove more.

## The losses Presidio adds

In the second pass Presidio destroys 384 terms in 220 of the 405 cases that ours left intact. Counted by the
entity type of the span that covered the term (a term can count twice):

| entity type | terms |
| --- | --- |
| ORGANIZATION | 198 |
| PERSON | 145 |
| LOCATION | 41 |
| NRP | 15 |
| US_DRIVER_LICENSE | 13 |
| URL | 11 |
| DATE_TIME | 5 |

Typical examples (public technical terms of the pack):

- Service names: Elastic Cloud Server, Object Storage Service, Cloud Eye, Direct Connect, NAT Gateway, Enterprise
  Router, Cloud Container Engine, Relational Database Service as ORGANIZATION or PERSON; Landing Zone, Transit
  Gateway and Anti-DDoS as LOCATION.
- Products and vendors: Terraform, Veeam, Proxmox, Fortinet FortiGate, Palo Alto Networks, Cisco Meraki vMX, Azure
  Site Recovery, Microsoft Defender for Cloud.
- Flavors and standards: s3.large.2, rds.pg.c6.large.4 and rds.pg.c2.large as URL or US_DRIVER_LICENSE; BSI C5 as
  US_DRIVER_LICENSE; c7n.2xlarge.2 as LOCATION; Windows Server 2022 as DATE_TIME.
- SQL and headings: FROM, WHERE, ORDER BY, LEFT OUTER JOIN; Fazit, Vorschlag, Nächste Schritte, Offene Punkte;
  section letters such as A. Einleitung.
- German and Russian table headers and roles: Vorname, Ansprechpartner, Telefon, Datum, Kürzel, Senior Cloud
  Architect, Stabsstelle Datenschutz and their Russian counterparts.

The `losses` dimension, built from the false positives our wipe was tuned against, loses terms in 41 of 45 cases.
With only PERSON, mail and phone the added losses drop to 142 terms in 110 cases, still mostly service names and
headings read as a person.

## Conclusion

1. Not worth adding as a second pass that rewrites the copy: it closes 3 of our 7 leaks and destroys terms in 220
   of 405 cases (384 terms), mostly TCP service names, products, flavors and headings.
2. As a flag-only second opinion on the laptop (report spans, never change the copy) it is possible but weak: the
   flags would be mostly service names and the owner would have to read through them.
3. Cost: about 1.4 GB installed (373 MB packages, 425 MB English model, 610 MB German model), 8 s load and 1.6 GB
   memory for both languages, about 0.09 s per case on top of our 0.76 s.
4. It closes tf-acr-vm-glued-hostname (ORGANIZATION), de-lone-after-preposition (PERSON) and
   ru-customer-translit-short-alone (PERSON); the last two each with a new loss.
5. The four lower-case or glued names in code and the German ordinary-word surname stay open; they need our own
   rules, not a name model.

Reproduce (scratch environment with the packages above, outside the repository):

    PYTHON calibration/redteam/wipe/presidio_compare.py --work DIR --json OUT
    PYTHON calibration/redteam/wipe/presidio_compare.py --work DIR --langs en
    PYTHON calibration/redteam/wipe/presidio_compare.py --work DIR --entities PERSON EMAIL_ADDRESS PHONE_NUMBER
