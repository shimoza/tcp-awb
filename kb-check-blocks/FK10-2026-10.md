# FK10: the check blocks of the 44 expired entries, October 2026

One section per entry. The lines under a heading are the block as `awb kb how ID -` takes them on standard
input (design `docs/strategy/F4-fact-check-design-2026-10-14.md`, section 1). The steering session applies them
on the host; this file is not merged. Every block carries a control. Paths follow the API reference of T Cloud
Public. No block names a price, a customer, a partner or a person.

No entry of this batch is a plain GET through the read key, so no block has the tier read: each needs a resource
the read key cannot make, a second domain, a person at a console, a change of stock over time or a call the key
service does not sign. A block that a new small recipe would cover names the recipe under `needs`
(`recipe NAME`), because a recipe that is not in `recipes/` may not stand under `calls`. Two blocks name
the existing recipe `ecs-flavor-boot` under `calls` and still take the tier decision, because the stock change
they record cannot be forced by a run.
